# Блоки городов

Каждый файл - готовый блок `город` для `hotel-config.json`. Заводится он один
раз и хранится здесь, потому что собирать его заново дорого: внутренние id
Trip.com и Agoda в открытом виде нигде не лежат, их смотрят в адресной строке
после ручного поиска города на каждом сайте.

```
node hotel-parser.js --city=danang --ci=2026-08-21 --co=2026-08-26
```

Флаг подставляет блок города и даты в `hotel-config.json` перед прогоном,
так что править файл руками не нужно. Без флага берётся то, что в конфиге
лежит сейчас.

## Зачем это появилось

17.08.2026 сессия по отелям Дананга началась с того, что в `hotel-config.json`
стоял Гуанчжоу с датами 29-30 августа, а копии дананговского конфига не было
нигде: каталоги прогонов `output/run_*` конфиг не сохраняют. Пришлось
восстанавливать - `cityid_trip` и `slug_ostrovok` нашлись в ссылках старой
выгрузки, `cityid_agoda` пришлось проверять живой страницей, а координаты
центра города - подбирать по расстояниям, которые Google посчитал от него
в прошлый раз. Полчаса на то, что должно лежать в двух килобайтах.

## Как добавить город

| Поле | Где смотреть |
|---|---|
| `cityid_trip` | ищем город на trip.com, в URL выдачи `cityId=1356` |
| `cityid_agoda` | ищем город на agoda.com, в URL выдачи `city=16440` |
| `slug_ostrovok`, `country_ostrovok` | URL отеля на ostrovok.ru: `/hotel/vietnam/da_nang2/...` |
| `query_booking` | текст, который вводится в поиск Booking; для ночёвки у аэропорта - название аэропорта |
| `query_trip` | латиницей, идёт в поиск Google и в подсказки Agoda |
| `lat`, `lng` | центр, от которого считается расстояние до отелей. Для транзитной ночёвки ставим аэропорт |
| `geocode_countrycodes` | двухбуквенный код страны для Nominatim в `build-report.js` |
